macOS Clash 入门：选对芯片、导入配置与代理设置

了解 Mac 的 Intel 与 Apple Silicon 安装包，完成 Clash 客户端首次配置，并检查门禁提醒、代理权限和退出恢复。

Clash 图鉴编辑 8 分钟更新于 2026.10.27

Mac 上的安装失败、代理无效和配置错误是三类问题。按“确认芯片 → 安装与来源核对 → 激活配置 → 开启代理”的顺序处理，能避免一开始就改动 DNS 或系统安全设置。

01先查看芯片与最低系统要求

在 Apple 菜单的“关于本机”查看芯片或处理器名称。Apple Silicon 通常对应 arm64 或 aarch64，Intel 对应 x64 或 x86_64；Universal 包是否可用，以项目发布说明为准。下载前也要核对最低 macOS 版本。

若使用 DMG，按安装窗口提示放入“应用程序”，然后从应用程序目录启动。升级前正常退出旧进程。不要一边运行旧版，一边反复覆盖同名应用；保留配置备份后再进行升级。

02把来源核验放在安全提醒之前

macOS 的门禁会检查外部应用的签名、公证等信息。出现“无法验证开发者”与“将损坏电脑”不应被当作同一种提示。先回到原始 Release 核对下载来源，并查看该版本是否有已知安装问题。

只有你确认应用来源可信且未被篡改时，才按 Apple 官方说明，在尝试打开后查看“系统设置 → 隐私与安全性”中的“仍要打开”。不要为了安装一个客户端永久关闭门禁，也不要直接复制来源不明的去除隔离脚本。

03激活配置后再开启代理

打开订阅或配置管理页面，导入远程订阅或本地 YAML 文件。确保当前配置可以加载，代理组中能选择你有权使用的节点，然后先选规则模式。尚未运行内核时打开系统代理，会让应用把请求发送到不存在的本机服务。

  1. 退出其他正在改写系统代理的工具，避免开关互相覆盖。
  2. 先用系统代理测试浏览器，检查连接记录是否出现对应请求。
  3. 测试常用局域网地址、同步工具和开发环境。
  4. 需要覆盖不遵循系统代理的应用时，再安装项目要求的辅助服务并测试 TUN。

04开关显示已开，不代表系统已应用

如果客户端开关变化，但浏览器连接记录没有请求，核对当前网络服务的代理设置是否真的改变。权限限制、受管理设备策略或其他网络工具都可能影响写入；不要假设“按钮亮起”就是成功。

管理员授权请求应与自己刚执行的安装服务、开启 TUN 等动作对应。公司或学校管理的 Mac 如限制网络扩展或服务安装，应联系设备管理员，而不是删除管理配置。

05完成 DNS 与退出恢复检查

TUN 可能影响路由和 DNS，客户端也可能为适配系统而临时调整网络设置。变更前记录当前 Wi-Fi 或以太网的 DNS 与代理设置，关闭 TUN 后再检查是否恢复。每个版本行为应以其官方文档为准。

出现断网先关闭 TUN、关闭系统代理并正常退出。若曾强制退出，重新启动客户端完成关闭流程，再检查系统代理是否残留。最后才启用开机启动，确认重启后仍能连接并正常退出。

常见问题

M 系列 Mac 应该下载 Intel 包吗？+

优先选择项目提供的 Apple Silicon 或 arm64 包。Intel 包是否可通过转译运行取决于应用与系统，不应作为默认选择。

看到“已损坏”就可以直接去除隔离属性吗？+

不应直接这样处理。先核对来源、重新下载并检查项目发布说明；Apple 提示可能涉及损坏、修改或恶意内容，应根据具体提醒处理。
