Windows Clash 入门：从安装包到第一次连接

使用 Clash Verge Rev 完成 Windows 安装、订阅导入、规则模式与系统代理检查，并处理架构或 WebView2 问题。

Clash 图鉴编辑 8 分钟更新于 2026.10.27

本教程以 Clash Verge Rev 的通用流程为例。不同版本的按钮名称可能变化，请以安装版本的官方说明为准。开始前准备有效配置，确认 Windows 系统类型，并暂时退出其他正在修改系统代理的客户端。

01下载与系统匹配的安装包

在 Windows“设置 → 系统 → 系统信息”中查看系统类型，再选择 x64 或 ARM64。不要仅凭电脑品牌判断。到客户端原始发布页核对版本，本站加速入口中的源文件应对应同一条 GitHub Release 附件。

当前 Clash Verge Rev 官方安装文档说明已不支持 Windows 7。旧系统不能靠改文件名解决兼容问题；应先确认项目系统要求，再决定升级系统或采用适合该环境的方案。安装前保存其他工作。

02界面打不开，先判断运行环境

若进程存在但窗口空白、只显示托盘图标，先查看官方 Windows 常见问题。Clash Verge Rev 的界面依赖 WebView2；缺失或被禁用时，面板可能无法显示。不要从不明资源站拼装 DLL 文件。

  1. 确认下载架构正确，安装器未被解压或改动。
  2. 检查 WebView2 是否可用；需要补装时从 Microsoft 官方来源获取。
  3. 只有官方说明适用时，才选择发布页提供的带 WebView2 安装包。
  4. 仍无法启动时记录客户端版本、Windows 版本和具体错误，再查对应问题。

03导入配置，先确认内核已运行

在订阅或配置页粘贴完整订阅地址，或导入已有的 YAML 文件。给配置取一个能区分来源和用途的名称，保存后将它设为当前配置。不要只看列表中是否出现一张卡片，还要确认激活没有报错。

进入代理页面，选择规则模式与一个可用策略组。首次测试先使用客户端默认端口，暂时不加入脚本、覆盖配置和额外规则。这样发生错误时，可以区分是基础配置失败还是自定义内容造成。

04开启系统代理并完成闭环检查

先开启系统代理，用遵循系统代理的浏览器访问你有权访问的测试页面，再在连接记录中核对目标域名、命中规则和出口。延迟测试的数字只能说明该测试请求的结果，不能替代真实网页加载。

  1. 确认普通网站和局域网服务仍能使用。
  2. 若只有某个程序不走代理，查看它是否支持系统代理；需要时再了解 TUN。
  3. 关闭系统代理并正常退出客户端，确认网络可恢复。
  4. 最后再设置开机启动，保留安装包版本和配置备份。

05退出后断网，检查残留代理

如果客户端被强制结束，Windows 的手动代理可能仍指向本机端口，而监听该端口的进程已经停止。先重新打开客户端并关闭系统代理；也可以在 Windows 的代理设置中核对手动代理状态。不要把重置整个网络作为第一步。

TUN 报错则先关闭 TUN，回到已验证的系统代理流程。提交排障信息时只提供必要日志，删除订阅地址、令牌和服务器密码。

常见问题

安装后为什么还没有节点？+

客户端本身不提供节点。需要导入你自己持有的有效订阅或配置，并将其激活。

需要一直用管理员身份运行吗？+

普通系统代理与需要权限的服务或 TUN 操作应分别判断。按客户端官方指引安装服务，仅在确有需要时授权，不要通过关闭系统安全功能排查所有问题。
