Clash 安装包 SHA-256 校验：Windows、macOS 与 Linux

使用 PowerShell Get-FileHash、shasum 和 sha256sum 核对 Clash 安装包，与上游可信校验值比较，并理解哈希一致的实际含义。

Clash 图鉴编辑 6 分钟更新于 2026.10.27

下载完成后，先计算安装包的 SHA-256，再与上游发布者公布的参考值比较。校验应在安装或解压之前进行。以下命令只读取文件，不会运行安装程序；示例文件名需要替换为实际下载的文件名。

01先取得可信的参考校验值

回到原项目的 GitHub Release 或官方校验清单，确认版本、系统、架构和文件名完全对应。加速服务转发的是附件，不应把同一陌生镜像提供的哈希当作独立来源。

有些项目不提供校验值。此时自己计算出的哈希只能用来记录或比较两次下载是否一致，不能据此宣称“已通过官方校验”。签名验证如有提供，应另按上游说明完成。

02Windows：使用 PowerShell Get-FileHash

在实际下载文件夹中打开 PowerShell，将下方文件名换成对应安装包。-LiteralPath 按字面读取路径，-Algorithm SHA256 明确指定算法。查看输出的 Hash，不要把文件路径当成校验结果。

Get-FileHash -LiteralPath '.\clash-client.exe' -Algorithm SHA256

03macOS：使用 shasum -a 256

打开终端并进入实际下载文件夹，针对下载的 DMG、ZIP 或 PKG 原文件运行命令。也可以输入 shasum -a 256 后，把文件从 Finder 拖到终端补全路径。输出第一列是摘要。

shasum -a 256 './clash-client.dmg'

04Linux：使用 sha256sum

在下载文件夹中对 AppImage、DEB、RPM 或压缩包本身计算摘要，路径含空格时保留引号。若上游提供符合工具格式的校验清单，可按其说明使用 sha256sum -c；不要对来历不明的清单盲目执行。

sha256sum './clash-client.AppImage'

05比较全部字符，再决定下一步

SHA-256 通常显示为 64 位十六进制字符，比较时核对全部字符，不只看开头结尾；大小写表示不影响数值。压缩包与解压后的程序是不同文件，摘要不能交叉比较。

  1. 确认本地文件与参考值使用同一算法，且对应同一发布附件。
  2. 一致时记录版本、文件名、参考来源与结果，再继续安装。
  3. 不一致时先停止安装，检查是否选错架构、文件是否未下载完整，重新从可信来源获取。

06哈希一致不等于软件安全保证

一致表明文件内容与该参考摘要相符，不能证明程序没有漏洞、恶意行为或已经过完整安全审计。若发布源和参考值同时被篡改，单纯比较哈希也无法解决来源问题。仍要核对仓库身份、发布说明与系统签名提醒。

常见问题

下载加速后的文件与 GitHub 原文件应有相同哈希吗？+

若确实是同一发布附件，转发没有改变文件字节，SHA-256 应相同。发现不一致时先停止安装，核对版本、架构、完整性与来源。

没有官方 SHA-256，还能校验吗？+

可以计算本地哈希作记录或比较，但缺少可信参考值就不能确认它与发布者原件一致。优先检查上游是否提供签名或其他验证方式，不要编造参考值。
