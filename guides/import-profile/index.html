Clash 订阅怎么导入：URL、本地 YAML 与更新排错

区分订阅链接和节点链接，按顺序完成 Clash 配置导入、激活与更新，并保护订阅中的访问凭据。

Clash 图鉴编辑 6 分钟更新于 2026.10.27

“导入成功”和“可以使用”之间还差两步：激活配置、选择有效出口。先分清手中的资料是什么，再判断错误发生在下载、解析还是连接阶段，比不停点击更新更有效。

01先确认是订阅、节点链接还是网页

订阅 URL 通常返回一份配置或可转换的数据；单个节点链接描述一个服务器；登录页、使用说明页和营销页面都不是配置文件。浏览器里能打开某个页面，也不能证明它是客户端可读取的 Clash 订阅。

向配置提供者确认支持 Clash 或 Mihomo 的格式，以及当前客户端要求。不能只把其他格式文件改名为 .yaml。如果节点列表存在，但缺少客户端需要的策略组或规则，仍可能无法按预期加载。

02导入远程订阅的稳妥顺序

菜单名称可能叫“订阅”“配置”或“Profiles”。在 URL 输入处粘贴完整地址，注意去掉首尾空格，保留查询参数。含令牌的长链接不是公开下载链接，本站 GitHub 安装包加速前缀不应套到订阅地址上。

  1. 创建远程配置并命名，执行下载或更新，等待明确结果。
  2. 确认未提示解析错误，再将其设为当前配置。
  3. 打开策略组，选一个可用节点或自动选择组。
  4. 开启所需代理方式，用真实访问和连接记录验证结果。

03本地 YAML 要注意副本和覆盖

从文件导入时先保留原始配置备份。部分客户端会把文件复制到内部配置目录，之后编辑下载目录里的原文件，不一定会改变正在运行的配置。修改前先确认编辑的是哪一份。

远程订阅更新可能覆盖本地直接改写的内容。需要自定义规则时，优先使用客户端文档支持的覆盖、合并或扩展配置方式，并先在副本上验证。缩进、引号和字段层级都可能造成 YAML 解析失败。

04按错误阶段定位问题

下载失败时，检查地址有效性、证书、时间与当前网络；如果收到的是登录 HTML 页面，应解决鉴权或链接问题。解析失败时，检查格式与内核兼容性。激活成功但不能访问，才继续检查节点、规则、DNS 与接管方式。

  • HTTP 401 或 403：可能涉及授权、令牌或访问策略，应向配置提供者确认。
  • 超时：区分配置服务器不可达与代理节点不可达，二者不是同一个测试。
  • 证书错误：先检查系统时间和证书链，不把跳过验证当作默认修复。
  • URL Scheme 一键导入失败：可退回手动 URL 或本地文件方式，避免重复跳转。

05更新、备份和分享时保护凭据

将更新周期设为实际需要的频率，失败时保留上一份可用配置。备份应放在你信任的位置，并考虑它可能包含密码、令牌和服务器信息；不要上传到公开 GitHub 仓库。

求助前删除订阅 URL 中的密钥、节点认证字段和账户信息，保留错误文本与相关字段结构即可。若完整链接已经公开，应在原服务端重置令牌，仅删除帖子并不一定能消除已经泄露的访问权限。

常见问题

可以把订阅交给任意在线转换网站吗？+

不建议。转换服务可能接触完整订阅和服务器凭据。优先使用配置提供者直接支持的格式，确需转换时选择自己信任并了解其数据处理方式的工具。

刷新订阅后自定义规则为什么消失？+

远程内容可能覆盖了直接编辑的配置。恢复备份后，按客户端文档使用覆盖或合并功能保存个性化设置。
